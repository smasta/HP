# コラムの図版・サムネイル生成

`web/scripts/` の2本のスクリプトに描画をまとめてある。**新しい絵柄はこの2本に関数を足す。**
別ファイルを作ると配色と質感がずれるので作らない。

| スクリプト | 用途 | 寸法 | 出力先 |
|---|---|---|---|
| `generate-column-figures.py` | 記事本文に差し込む図解 | 1600×900 | `web/public/images/columns/fig-*.jpg` |
| `generate-column-keyvisuals.py` | 記事ごとのサムネイル | 1200×630 | `web/public/images/columns/{slug}.jpg` |

```bash
cd web
python3 scripts/generate-column-figures.py .
python3 scripts/generate-column-keyvisuals.py .
```

`generate-column-covers.py` はニュース用の抽象モチーフを流用する古い経路。
`KEYVISUALS` に slug がある記事には手を出さないので、`--force` でも上書きされない。

## 共通の描画仕様

両スクリプトが同じ値を持っている。**変えない。**

```python
SS = 3                       # 3倍で描いて縮小する。輪郭が滑らかになる
INK_DEEP = (7, 12, 24)       # 地色（上）
INK      = (15, 23, 42)
INK_SOFT = (22, 32, 60)      # 地色（下）
INDIGO   = (129, 140, 248)   # アクセント。捉えにくい側・対応する側
EMERALD  = (52, 211, 153)    # アクセント。把握できる側・着手できる側
MIST     = (147, 162, 191)   # 補助線・注記
MIST_LT  = (199, 210, 228)   # 本文級の説明
WHITE    = (255, 255, 255)

FONT_W3 = "/System/Library/Fonts/ヒラギノ角ゴシック W3.ttc"
FONT_W6 = "/System/Library/Fonts/ヒラギノ角ゴシック W6.ttc"
```

- 保存は `save()` に通す。`resize((W, H), Image.LANCZOS)` してから
  JPEG quality 88 / optimize / progressive / subsampling=0。
- 地とグリッドは `base()` で作る。自前で塗らない。
- 意味の対応を崩さない。**EMERALD＝できている側、INDIGO＝できていない側／次の段階**。
  この対応は既存4図で一貫しているので、新しい図でも守る。

### 使えるヘルパー

両方にあるもの — `lerp(a, b, t)` / `base()` / `save(img, path)`

`generate-column-figures.py` だけにあるもの（文字を扱うため）
`font(size, bold)` / `center_text(d, box, text, f, fill)` / `wrap(d, text, f, width)` /
`center_lines(d, box, lines, f, fill, leading)` / `arrow(d, x, y, fill, size)`

`generate-column-keyvisuals.py` だけにあるもの
`gradient_bar(box, top, bottom, radius)` — 縦グラデで塗った角丸を layer/mask/pos で返す
`glow(img, draw_shapes, blur, strength)` — 図形をぼかして加算合成し発光させる

keyvisuals 側は文字を描かない設計なので ImageFont を読み込んでいない。
サムネイルに文字を入れたくなったら、それは設計を間違えている（上の制約を読む）。

## サムネイルの制約（ここを外すと崩れる）

cover は**3か所で使い回される**。

1. 一覧カード — `aspect-[16/10]` に `object-cover` で切り取られる（1200×630 なら中央1008pxだけ残る）
2. 記事ヒーロー — **上に記事タイトルが重なる**
3. OG画像

このため、

- **文字を入れない。** 図形だけで内容が伝わる構成にする。
- **中央に寄せる。** 内容は横 x=120〜1080 の範囲に収める。
- カードサイズ（440×275程度）に縮小しても判別できるか、必ず縮小して目視する。

## 本文図版の作り方

サムネイルと違い、こちらは文字を入れてよい。ただし読ませるための図なので、

- 見出し（30pt bold・白）とサブ（19pt・MIST）を左上、`92*SS` の余白に置く。
- **出典を図内に明記する。** 16pt・MIST の85%で「出典：〜 をもとに作成」。
  制度の図なら告示番号や条項まで書く。位置は最下部 `CH - 74*SS` が既定だが、
  上に行数の変わる要素（表・凡例）があるときは、そこから積み上げて算出する。
- 図の中の制度名・条文・項目名は**指針や法令の原文表記にそろえる**。要約しない。

## 手順

1. **事実を一次資料で確認する。** 官公庁のPDFを `pdftotext -enc UTF-8` に通し、
   図に書く文言を原文と突き合わせる。記憶で書かない。
2. 記事のどの主張に対応する図かを決める。記事の骨子が2つなら図も2枚。
   既存の `callout` や `table` と内容が丸かぶりする図は作らない
   （図は構造を、テキストは解釈を担うよう役割を分ける）。
3. スクリプトに関数を足し、`main()` から呼ぶ。
4. **生成した画像を実際に開いて見る。** ここを飛ばさない。
   行の重なり、折り返しの破綻、上下の余白の偏りはコードを読んでも分からない。
5. `web/lib/columns.json` の `body` に `image` ブロックを挿入する。
6. ビルドして生成HTMLに `src`・`alt`・`caption` が入っているか確認する。
7. コミットしてプッシュ、本番反映と画像の200を確認する。

### columns.json への挿入

```json
{
  "type": "image",
  "src": "/images/columns/fig-....jpg",
  "alt": "図の内容そのものの説明。何がどう配置され、何を色分けしているか",
  "caption": "その図が示している主張。本文の言い換えではなく要点"
}
```

`alt` と `caption` は役割が違う。`alt` は画像が見えない人に**図の中身**を伝えるもので、
`caption` は**読者に何を読み取ってほしいか**。同じ文を入れない。
挿入したら記事の `updatedAt` を更新する。

## 過去に踏んだ失敗

- **文字単位の折り返しは破綻する。** 「安全衛生管理体制の確立等」が
  「安全衛生管理体制の確／立等」と割れた。長い名称は `\n` で改行位置を持たせる。
- **行数から座標を計算する。** 行高を見積もって凡例や出典のYを固定すると、
  行が増えたときに重なる（fig-six-traits で発生）。
- **空き枠の中に破線を引かない。** 読み込み中のスケルトンに見える。輪郭だけにする。
- **上下の余白が偏る。** 図形を上寄せにすると下が大きく空く。
  生成後に見て、上下の余白が釣り合う位置まで全体を下げる。
- **同じ絵柄を使い回さない。** ニュース用の抽象モチーフ（波形・六角形）を
  コラムに流用していたが、記事の内容と無関係で意味がなかった。

## 表記のルール

`web/docs/column-backlog.md` の執筆ルールが図版にもそのまま効く。

- **効能を断定しない。** 「転倒を予防できる」「認知機能が改善する」は景表法・薬機法の
  リスクがある。「測定する」「可視化する」「把握する」と書く。
- **日本語で書く。** 固有名詞以外の外国語を使わない（例：VR →「仮想現実の技術」）。
  ただし指針の原文にある片仮名語（ワークシェアリング等）は原文どおりでよい。
- 測定は診断ではない。医学的な判断は産業医等が行う、という線を越えない。
